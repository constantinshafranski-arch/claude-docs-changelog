Hooks reference

Updated

Expanded hook scoping documentation to clarify that hooks fire inside subagents, how hook entries merge across settings levels, and how HTTP allowlists apply to all hook sources including managed policy settings.

  • Subagent hook propagation — Hooks from settings files, managed policy settings, and plugins now run inside subagents; PreToolUse and PostToolUse events fire for subagent tool calls with agent_id and agent_type fields in common input
  • Hook merge behavior — Hook entries merge across settings levels (user, project, local) rather than replacing each other; the disableAllHooks setting cannot disable managed hooks from outside managed settings
  • allowedHttpHookUrls — When defined at any settings level, Claude Code runs an HTTP hook handler only if its URL matches the merged allowlist across all sources including managed policy
  • httpHookAllowedEnvVars — When defined, Claude Code interpolates only the environment variables on this list into hook headers, applying to hooks from every source

Configure the sandboxed Bash tool

Updated

Added documentation for the new strictAllowlist network sandbox setting (v2.1.219+) that denies sandboxed command network access to hosts outside the allowlist instead of prompting.

  • strictAllowlist — New network.strictAllowlist option (v2.1.219+) silently denies sandboxed commands access to hosts not in the allowlist (allowedDomains plus WebFetch allow rules) instead of prompting; in-process tools such as WebFetch are unaffected
  • Settings scope restriction — strictAllowlist is only honored from user, managed, or CLI --settings sources; setting it in .claude/settings.json or .claude/settings.local.json has no effect
